# Security / 安全报告

[English](#reporting-security-issues) · [简体中文](#报告安全问题)

## Reporting security issues

Do not post API keys, personal learning materials, workspace backups or private credentials in public issues. Revoke an exposed key with its provider before sharing diagnostic information.

Once this repository is public, use GitHub's private vulnerability reporting channel if the maintainer has enabled it. Otherwise, request a private reporting channel without posting the vulnerability or credentials publicly. A dedicated contact and supported release policy must be established before public distribution; this document does not claim that either channel is currently available.

Include the affected version or commit, operating system, browser or WebView version, reproduction steps and a redacted error message. Avoid uploading full browser profiles or credential-store contents.

For current data handling, see [Privacy](docs/PRIVACY.md). Build and verification steps are documented in the [build guide](docs/BUILD_AND_RELEASE.md).

## 报告安全问题

请勿在公开 Issue 中发布 API 密钥、私人学习材料、工作区备份或其他凭据。若密钥泄露，请先到服务商处撤销，再提供经过脱敏的诊断信息。

如果维护者已启用 GitHub 私密漏洞报告，请使用该渠道；否则请先请求私密联系渠道，不要公开漏洞细节或凭据。正式分发前，需要建立明确的联系渠道和受支持版本政策；本文不代表这些渠道已经可用。

报告请包含受影响版本或提交、操作系统、浏览器或 WebView 版本、复现步骤和脱敏错误信息。请勿上传完整浏览器配置或凭据存储内容。

数据处理方式见[隐私说明](docs/PRIVACY.md)。构建和验证步骤见[构建说明](docs/BUILD_AND_RELEASE.md)。
